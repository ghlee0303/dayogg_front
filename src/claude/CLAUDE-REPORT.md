# Report 작성 규칙

## 개요

코드 리뷰(`CLAUDE-CODE_REVIEW.md`)가 특정 파일의 세부 이슈를 다루는 것과 달리,
Report는 **도메인·모듈 단위의 설계·구조 문제**를 정리하는 문서다.

- 저장 위치: `src/claude/report/`
- 파일명: `MMdd-[주제].md` (예: `0706-player-refresh-report.md`)

---

## Report 형식

```markdown
# [대상] Report

**날짜:** YYYY-MM-DD
**범위:** 문제가 있는 디렉토리 또는 계층 (예: `pages/player/`, `contexts/`, `hooks/`, 전체)

---

## 배경

이 Report를 작성하게 된 맥락이나 계기를 1~3문장으로 기술한다.

---

## 문제 요약

| 분류 | 건수 |
|------|------|
| 🔴 설계 결함 | N |
| 🟡 구조 개선 | N |
| 🟢 일관성·명명 | N |

**핵심 문제:** 가장 시급한 문제를 한 줄로 요약.

---

## 문제 목록

### 🔴 1. 문제 제목

**위치:** `디렉토리 또는 파일 경로`

**문제**
무엇이 잘못되었는지 설명한다.

**영향**
이 문제가 런타임·유지보수·확장성에 미치는 영향을 기술한다.

**개선 방향**
구체적인 해결 방법 또는 접근 방식을 기술한다.

---

### 🟡 2. 문제 제목

**위치:** `디렉토리 또는 파일 경로`

**문제**
...

**영향**
...

**개선 방향**
...

---

## 조치 우선순위

| 순위 | 항목 | 이유 |
|------|------|------|
| 1 | 🔴 N번 제목 | 런타임 영향 있음 |
| 2 | 🟡 N번 제목 | 확장 시 병목 가능 |
| 3 | 🟢 N번 제목 | 코드 일관성 |
```

---

## 작성 기준

### 심각도 분류

| 등급 | 기준 |
|------|------|
| 🔴 설계 결함 | 런타임 오류, 상태 정합성 문제(무한 로딩·무한 루프·경쟁 조건), 확장 불가 구조 |
| 🟡 구조 개선 | 유지보수 비용 증가, 컴포넌트·훅·컨텍스트 책임 혼재, 불필요한 상태 끌어올리기·prop 드릴링, 중복 로직 |
| 🟢 일관성·명명 | 코드 스타일, 네이밍, 불필요 코드, 미사용 변수·타입 |

### 작성 원칙

- **위치**는 `파일 경로:함수명`(컴포넌트·훅·컨텍스트 이름) 또는 디렉토리까지 명시한다. (예: `src/pages/player/index.tsx:sseRefresh`)
- **문제**는 "무엇이 왜 문제인지"를 코드 예시와 함께 기술한다.
- **영향**은 실제 발생 가능한 결과(장애, 버그, 병목)를 구체적으로 쓴다. 영향이 없으면 "없음 (코드 품질)"으로 명시한다.
- **개선 방향**은 방향만 제시하고 구현 코드는 별도 작업 시 작성한다.
- 코드 리뷰(`code_review/`)에서 이미 다룬 파일 단위 이슈는 중복 기재하지 않는다.
- `조치 우선순위` 섹션은 이슈가 3건 이상일 때만 작성한다.
