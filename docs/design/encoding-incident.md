# 한글 인코딩 손상 및 복구 리포트

- **발생일**: 2026-07-13
- **원인**: Tailwind v4 마이그레이션 중 클래스 일괄 치환을 PowerShell 5.1로 실행하면서 인코딩을 지정하지 않음.
  `Get-Content -Raw`가 UTF-8 파일을 시스템 ANSI 코드페이지(CP949)로 읽어 한글이 깨졌고, `Set-Content -Encoding utf8`이 그 상태로 다시 저장하면서 BOM까지 추가됨.
  ASCII(코드·클래스명·들여쓰기)는 전부 무손상, **비ASCII(한글)만 손상**.
- **결과**: 15개 파일이 스크립트 대상이었고 그중 **한글이 포함된 10개 파일 / 75개 라인**이 손상 → **전부 복구 완료**.
- **검증**: 무효 UTF-8 0건, BOM 0건, 모지바케(한자) 잔존 0건, `tsc --noEmit` 통과, `vite build` 성공.

| 유형 | 설명 | 예시 |

## 2. 복구 방법

1. **백업**: 손상 상태 파일 15개를 그대로 백업 (`%TEMP%\claude\C--dev-claude-front\...\scratchpad\backup_corrupt`).
2. **BOM 제거** 후 **역변환**: `iconv -f UTF-8 -t CP949` 로 원본 바이트를 되살림 → 줄바꿈/따옴표 등 **구조는 완전 복구**, 한글은 `?` 유실분을 제외하고 복구.
3. **원문 대조 복원**: 남은 유실 글자는 아래 두 출처의 원본으로 라인 단위 교체.
   - **VS Code 로컬 히스토리 스냅샷** (`%APPDATA%\Code\User\History`) — 주석·UI 문자열 모두 보유
   - **손상 직전 빌드 산출물** `dist/assets/index-D04jjJ15.js` — UI 문자열 보유(주석은 제거되어 없음)

## 5. 재발 방지

PowerShell 5.1에서 소스 파일을 일괄 치환할 때는 반드시 인코딩을 명시할 것.

```powershell
# 잘못된 예 — ANSI(CP949)로 읽고 BOM 붙여 저장
$s = Get-Content $f -Raw
Set-Content $f $s -Encoding utf8

# 안전한 예 — UTF-8(BOM 없음) 고정
$s = [IO.File]::ReadAllText($f, [Text.UTF8Encoding]::new($false))
[IO.File]::WriteAllText($f, $s, [Text.UTF8Encoding]::new($false))
```

더 안전한 대안은 Node(`fs.readFileSync(f, 'utf8')`)나 `sed`(Git Bash)처럼 기본이 UTF-8인 도구를 쓰는 것입니다. 또한 이 프로젝트는 git 저장소가 아니라 되돌리기가 어려웠습니다 — `git init` 후 커밋 이력을 남겨두면 이런 사고를 한 번에 복구할 수 있습니다.
